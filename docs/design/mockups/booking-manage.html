What this asserts — argue with it

  • One page, capability-URL, no login (DEC-122). The booking link is a bearer token — whoever holds it can manage the booking. That's why the confirmation email/SMS says "save this link", and why the recovery flow re-sends the existing link rather than showing it from typed input.
  • The link is the durable handle for the whole lifecycle: before the trip it shows details + balance + cancel; after, it flips to the post-trip tip + receipt + rebook. Same URL, state driven by trip time — the customer bookmarks one thing.
  • Repeat customers see their past trips here. We have repeat guests, so the manage page lists the contact's other reservations (past + upcoming), each a click away. DEC-122 implication: surfacing history from one link means holding any one link exposes all that contact's trips — acceptable (same person), a conscious bearer-token loosening to record.
  • Boat never named to the customer; crew are. The hull is assigned behind the scenes and never shown — but once the captain + mate are assigned, their names appear on the trip (operator liked this). Boat = logistics, hidden; crew = the people you're trusting, shown.
  • Balance is shown, not hidden. Deposit paid + balance auto-charged 3 days before (Jul 15 for a Jul 18 trip) — deposit is a flat $100 (a system admin setting; flat-or-% and timing are configurable). Pay-in-full bookings show a single "Paid in full" and no balance row.
  • Cancel is self-service for Flex holders (DEC-107, amended — customers self-refund; refunds aren't manual-only). "Full refund up to 24h before" with the concrete deadline. Non-Flex bookings show a different cancel state (fee or no-refund) — that copy is Drew's call, not mocked here.
  • Post-trip tip is the DEC-124 post gratuity, first-class. Framed as "+% on top" of the pre-tip already paid, optional, three positive tiers, 100% to crew. This is the reason the phone number earns its place on the booking form — it's how we reach them to tip after.
  • Guests sign the waiver ahead of time (DEC-110). The booking guest sends the waiver link to everyone; each guest signs and leaves a name + phone, which builds the guest list and is how we text every passenger on the reservation (trip reminders, crew updates). Not a dock-signed roster.
  • Settled 2026-07-17: the customer can change date/time from here (reopens the picker); the message action reaches the operator ("Message us"), never the crew; the boat name is never shown — the captain + mate names appear once assigned instead; non-Flex cancel terms come from admin settings, not this mockup.
