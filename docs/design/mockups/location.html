What this asserts — argue with it

  • Location is its own entity, not a text field on the Offering (DEC-123). One edit updates pickup + route everywhere it's used, and it gives location blocks something to target.
  • Carries pickup [description + link] and a route description — the two things a customer needs and the operator would otherwise retype per offering. The Offering just references it via a picker.
  • "Block this location" lives here as an entry point, but the block itself is created on the Blocks surface (DEC-125) — one place owns availability subtraction. This button is a shortcut, not a second block model.
  • "Used by" is read-only — the Offering owns the reference. Prevents two screens both claiming to set the same link.
  • No location photo, and one time zone (operator, 2026-07-17). The map link is enough for the pilot — no lat-long, no map pin, no photo. Time zone stays the tenant's single vessel-local zone (Cleveland); a per-Location zone is a second-market problem, and inventing the column now would be modelling for a market that doesn't exist. Both are additive later — a photo is a column, a zone is a column, and neither reshapes anything that reads a Location.
