What this asserts — argue with it

  • The front door of the customer funnel. Offerings list → availability picker → booking form. This page answers "what can I book?"; the next two answer "when?" and "who + pay."
  • One card per Live offering. BrewBoat runs a single offering today, so it's one card — but the page is a list that scales: add an offering, flip it Live, it shows up here. No layout change for one vs. five. Draft and Hidden offerings never appear (the same Draft/Live/Hidden flag from the admin offering screen).
  • The card is a teaser, not the detail. Photo, name, location + duration, "up to 16" as capacity, and "from $399" — the offering's lowest schedule price (Sunday). Tapping "See times" carries the offering into the availability picker; nothing is chosen or priced here.
  • "from $399" is honest and low. It's the cheapest real slot (schedule-driven), not a bait number — the calendar on the next page shows the actual per-day/per-time price. Whole-boat framing ("up to 16," no headcount) matches the rest of the funnel.
  • Brand hero, not a hero image of one boat. This is the operator's storefront, so it leads with BrewBoat, not a single vessel — the customer picks an experience, the system picks the hull later.
  • One Live offering skips this page (operator, 2026-07-17). With a single offering the customer goes straight to its availability picker; this catalog only appears once there are 2+ offerings. So today the screen is dormant — it earns its place when BrewBoat adds a second offering.
  • No filter, no sort, no sold-out state — just the list (operator, 2026-07-17). Nothing to filter at one offering, and a card that says "sold out this week" would be answering a question the customer hasn't asked yet: availability is the picker's job, one tap away. The card stays a teaser. Revisit filtering if the catalog ever gets long enough to need it — which is a problem BrewBoat doesn't have.
