What mobile does differently — argue with it

  • Not the grid. 4 boat columns × 5 times is unreadable at 375px. Mobile is a list grouped by departure time, boat named on each row. Same 20 events, scannable with a thumb.
  • Boat name takes any length. It's out of the fixed 52px column and into the flow line ("Brew 1 · 12 guests · $499"), so a long name pushes off the price — the least important thing on the row — instead of truncating the name. The hue dot does the at-a-glance identification, which is why the name can afford to be secondary. On desktop the name is a column header — 4 times, not 20, so the repetition problem is mobile-only and the header flexes to fit.
  • Filter chips move up top and stay stuck while the list scrolls — at 20/day the filter is how you use the screen, so it can't scroll away.
  • Sell is on the row. No hover on a phone, so the button is always visible on open slots rather than revealed.
  • Actions pin to the bottom bar, in the thumb's reach — Message and Guests get the room, everything else is behind ···. On desktop those six buttons sit in a row; here that would be a wall.
  • Detail is a screen, not a pane. Back link returns to the day. Same content, sectioned into cards so it reads while scrolling.
  • Open slots keep the dashed border — the one visual carried straight over from desktop, so the two form factors agree on what Open looks like.
  • Opens on All — settled (operator, 2026-07-15). Not "Open only", for now.
  • Settled 2026-07-17: approved as-is — no Week on mobile (day list + date nav is enough on a phone); the ＋ new-booking stays in the header.
