What this asserts — argue with it

  • Capacity is a Vessel fact, set once, here (DEC-123). Brew 1 = 12, Brew 4 = 16. Offerings and pricing read it — never override it. This is the single source for the customer's "up to N" ceiling and the whole-boat max.
  • Color is information, not decoration (DEC-021/042 palette lock). The vessel's hue identifies it on the reservation calendar and the crew shift board — so it's a Vessel fact too, chosen from the locked palette.
  • Out-of-service is NOT a field on this screen — it's a vessel block (a date range) on the Blocks surface (DEC-125). The "Take out of service" button is a shortcut into that flow. A boat down for a week is a block, not a status flip, so availability recomputes and the dates are audited.
  • Retire = a soft archive (the "In service" pill's other state), same reversible-soft-delete idea as an Offering's Hidden — a sold hull is never hard-deleted. (Distinct from a temporary block.)
  • "Runs" is read-only. The Offering owns which vessels it uses; showing it here is just the reverse lookup.
  • One Vessel. Not a twin. (Settled — operator, 2026-07-17.) This IS the vessel the crew engine already knows. There is no reservation-side copy and no sync between two tables — the earlier "twin that maps to it" framing is rejected. They don't "meet at the vessel-day" because they were never two things.
