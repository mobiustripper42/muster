## Task 1: Phase 2.1 / Pass A (#30) — reliability scorer: blended score from logged events

**Completed:**
- **The Pass-A mechanism** (`src/oracle/reliability-score.ts`, framework-free + pure): `computeReliabilityScore(events, now, opts?) → {score, eventCount, windowEvents}` turns a crew member's append-only `ReliabilityEvent` log into one blended **ranking signal** (SPEC §1.4, DEC-008). Neutral-0 baseline (cold start = mid-pool, lines up with `rankPool`'s `?? 0`), additive **sum** over a **count-based rolling window** (most recent `WINDOW_EVENTS`, default 40 ≈ a season, tunable), **decline-neutral** (`ask_declined` = 0), **`ask_ignored` the lone ask penalty**, **bail-lateness-scaled** penalty (`metadata.latenessMs`, higher=later=worse, linear) on top of a flat bail weight, `no_show` the floor. All weights + window tunable via `DEFAULT_WEIGHTS`/`opts` — the Pass-A tuning lever, deferred until real data.
- **Design pivot (Eric, post-review): count-based window, not calendar.** Original cut used a 90-day calendar window; Eric flagged that BrewBoat is seasonal — an off-season gap (~8 months) is longer than any sane calendar window, so every returning veteran would reset to neutral each spring (flat ranking exactly when staffing up). Count-based window carries history across the gap (off-season has no events to consume the count). Added a **seasonal regression test** for it.
- **Parked in `docs/FUTURE_IDEAS.md`** (Eric, explicitly v1-deferred): (1) **volume-neutral scoring** — sum means rookies sit near the bottom; weighted-average/confidence blend is fairer but changes the number's meaning, wants real data. Sum stays for v1. (2) **inverse-exponential bail-lateness** — linear under-penalizes the truly last-minute bail; steep near-call ramp is the real curve. Linear stays for v1.
- `scoreCrewMember(repo, crewId, now, opts?)` — thin port bridge (`reliabilityEventsFor` → pure fn), `now` injected, no clock read.
