## Task 1: Phase 3.1b / #44 — magic-token reaper (separate auth aggregate)

**Completed:**
- **`reapExpiredMagicLinks(repo, now)` in `src/auth/magic-link.ts`** — sweeps `MagicToken` rows past `expiresAt` out of storage, returns `{ reaped }`. The auth half of the #39 split (@architect, 2026-06-09): different aggregate from the shift state machine, only rode along on the word "expiry." Reaps **by expiry only** (`cutoff >= Date.parse(expiresAt)`) — deliberately the *same* predicate `verifyMagicLink` uses to reject a link as dead, so reaper and verify never disagree (a link is never reapable while still redeemable). Consumed-but-unexpired tokens left for a later sweep (out of #44 scope). Injected `now`, no clock read, no scheduler v1 (DEC-023 sibling).
- **New `removeMagicToken(id)` port method** (`src/ports/repository.ts`) mirroring `removeSeat` — hard delete, no soft-mark flag on the entity (a single-use short-lived link past expiry is dead weight with no children). Implemented in both adapters: in-memory `Map.delete`, Postgres `delete from magic_tokens where id=$1` (no DDL change). `MagicTokenId` import added to port + Postgres adapter.
- **Tests:** 4 reaper unit cases (seeded clocks — expired-vs-live, `now === expiresAt` boundary, empty store, mixed-batch count) + a `removeMagicToken` contract test (delete + absent-id no-op) held against both adapters. `npm run verify` → 243 pass / 1 Docker-pg skip / build green (+5 over main's 238).

**Code review:** @code-review (Sonnet) — **Clean bill of health.** Boundary verified identical to `verifyMagicLink`; port/adapter consistency + round-trip safety confirmed. One parking-lot note (not this PR): N individual deletes vs a set-based `delete ... where expires_at <= $1` — fine at v1 volumes, revisit if a hosted cron sweeps a large backlog.
