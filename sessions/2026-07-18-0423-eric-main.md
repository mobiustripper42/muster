**Design notes worth remembering:**
- **Hold id is a unique per-attempt MINT, NOT slot-derived.** A slot-deterministic id made two buyers of one slot share an id → `acquireCheckoutHold` read the 2nd as idempotent re-acquire → contention hidden (tests caught it). One-per-slot = the `checkout_holds_slot_identity` unique; a won booking releases by SLOT (`removeCheckoutHoldForSlot`), since the mint isn't recomputable in the webhook.
- **Lazy expiry, no cron:** an expired hold reads free everywhere (deriver filters `expiresAt > asOf`); acquire deletes-expired-for-identity first so a stale row can't block a fresh acquire. Invariant: holds are ONLY read through the expiry filter — never raw-counted.
- Hold is optimization; `saveBookingIfSlotFree` CAS is the authority (never gate the write on a hold).
