## Task 5: Gate the Stripe webhook on RESERVATIONS explicitly (#588)

**Completed:**
- The gate lives in the **core** (`src/reservations/booking-webhook.ts`), because verification is
  there — `parseEvent` is the first line and throws on a bad signature. Flag injected as
  `reservationsEnabled: boolean`; the core never reads `process.env`. **Required, not
  optional-defaulting-true** — a default lets a future caller skip the gate silently.
- **Alerts, not just acks.** Reaching the branch means a verified charge SUCCEEDED and we chose
  not to book it. With the flag off nothing can mint a new intent, so it's a replay, a dashboard
  send, or a flag-on leftover — money already moved in all three.
- `reservationsEnabled()` in `app/lib/flags.ts`; five hand-spelled
  `process.env.RESERVATIONS !== "true"` collapsed onto it. Same shape as the auth-sweep defect
  where `dev-link` kept its own copy of the prod kill-switch. Left `"true"` vs the siblings' `"1"`
  alone deliberately — it's set in deployed envs, and changing the accepted value turns the
  feature off on a deploy nobody re-read.

**Code review found a real money regression, mine, and this is the one to remember.** I first put
the gate right after signature verification — the position that *looks* safest. It sits ahead of
purpose dispatch, and **balance + post-trip gratuity collection ride the same webhook against
existing reservations**. `createBalanceLink` is admin-gated with no RESERVATIONS check, and the
flag is **off by default** — so in a default deployment Stripe charges the customer for the
balance, `recordBalancePayment` never runs, and the operator gets an alert about new-booking
readiness describing something that didn't happen. Moved into `processBookingCharge` (booking path
only). Side benefit: DEC-134 shadow intents now return before the gate, so no double-alert.

**Two negative controls run:** gate above `parseEvent` → the bad-signature test reddens (that
ordering is what stops the flag being used to probe the endpoint); gate back at the original
placement → the **balance** test reddens. Only a test exercising the *other purpose* could tell
the two placements apart — which is exactly why it shipped green in my first pass.
