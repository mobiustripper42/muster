## Task 1: The backwards-amendment guard now runs for every DEC id family (#589)

**Completed:**
- `rank(id)` + `compareDecisionIds(a, b)` in `scripts/gen-decisions-index.mjs` — one ordering
  source for the guard AND `sortKey`, so display order and the check can't drift apart (the
  issue flagged sortKey's numeric-only branch as the same root assumption).
- `checkAmendmentEdge(from, to)` extracted in `scripts/check-decisions.mjs` as a pure function,
  with a **third** outcome: earlier → pass, not-earlier → the existing failure, **uncomparable →
  a red build naming the pair**. The old code bailed whenever either id missed `^DEC-(\d+)$`,
  so it never ran for DEC-DATA-1, DEC-MSG-1/2/3, DEC-ROLE-1, DEC-TBD.
- `docs/DECISIONS.md` regenerated — 10 lines, the five family rows moving to their chronological
  slot. DEC-TBD doesn't move (alone under *Open questions*).
- 12 tests. **Negative control ran:** reverting the guard turns exactly 3 red, nothing else.

**14.5 is evidence, not taste.** The pre-split DECISIONS.md was chronological and put all five
families between DEC-014 and DEC-015 (`f41a895^:docs/DECISIONS.md:374–472`). That number is
load-bearing because **the id is the only time proxy the record has** — no decision file carries
a `decided:` field. Worth remembering before anyone touches DEC numbering again.

**Cross-family stays uncomparable on purpose.** The pre-split file also gives MSG < ROLE < DATA,
but that's document order within one sitting, not evidence about when each was decided. Ranking
off it would manufacture a fact the record doesn't have. So `DEC-MSG-2 amends DEC-ROLE-1` now
**fails the build** — inert today (37 edges, none non-numeric), and if one is ever wanted it takes
a human decision rather than a config toggle.

**Renumbering the families was considered and rejected — no issue filed, operator's call.** There's
no gap between 14 and 15, so it would have to append: `DEC-DATA-1` → `DEC-143`, an id claiming to be
the newest decision when it's the 15th-oldest. That inverts the very invariant this guard asserts.
The strictly-better version — add `decided:` frontmatter, guard on dates, ids become pure labels —
is a real architecture change (~140 backfills, recoverable only approximately from `git log -S`).
Cost of the rename alone if it ever comes up: 373 occurrences across ~140 files (DEC-DATA-1 146,
DEC-ROLE-1 72, DEC-MSG-* 111, DEC-TBD 44), and it would silently stale the session files on the
orphan `sessions` branch.

**Code review:** Clean. Notable because the reviewer re-derived the claims rather than trusting them
— re-ran the generator to confirm byte-identical output (fixed point holds), traced every path where
`null` reaches a caller, and reimplemented the pre-fix regex to reproduce the negative control itself.

## Task 2: Declared spec amendments — the DEC→SPEC leg of the rot pattern (#590)

**Completed:**

  declaration with no scope, stale blocks, or `**` in a scope. `parseFrontmatter` generalized —
  it hardcoded `- id:`, so `- section:` couldn't parse. DEC-143 records it, extending DEC-141.
- 16 declarations across 14 decisions, 9 sections annotated. 13 new tests (43 total).
- **`LOCKED v1.0` stamp deleted** (operator's call, mid-task). DEC-014's live half kept.
  `.claude/CLAUDE-context.md` repeated the claim and had drifted on counts (said 139 / DEC-001–141).

**The conversion pass was the task; the mechanism was small.** The issue estimated "6 files, 7
claims — a quick pass." Actual: 47 files reference `SPEC §` in four prose shapes, mixed with
`implements` / `refines` / `cited by` relations that are NOT amendments. Estimated 5, took 5.

**Three findings, and the first is the one to remember:**
1. **SPEC §1.3 credited DEC-138 twice** (`:267,310`) for what is DEC-140's rewrite — fallout from
   last session's collision renumber. It never *dangled*, because DEC-138 is a real decision, so no
   check was ever capable of catching it. **A wrong-but-real reference is invisible to every guard
   we have** unless something checks the claim's substance.
2. Three claims had never landed (DEC-061→§2.6, DEC-140→§1.3). DEC-045→§2.6.3 is NOT a claim —
   it says outright it's "not a correction to the frozen v1.0 baseline." Excluded deliberately;
   sweeping in non-amendments is how the signal dies.
3. DEC-016 cites "SPEC §1 glossary"; the glossary is §0.4.

**Code review found a defect and it was mine, in the content not the code.** DEC-085's scope said
the board groups "day → boat" — it's **day → time**, with vessel identity as a hue and explicitly
NOT a grouping axis. I wrote it from a truncated read of the decision's own line, and the mechanism
had already published it into SPEC §2.3 as a *checked* pointer. **`check:decisions` verifies an
anchor resolves and a pointer landed — never that the text is true.** The generator makes a false
claim more authoritative, not less. Also fixed: the no-scope guard tested falsiness, so a
whitespace-only scope rendered an empty banner.

**Asked to strip redundant prose pointers from SPEC and didn't — reported instead.** Nothing in the
annotated sections is purely a reciprocal pointer; every hand-written citation is inline on the
bullet it corrects or is a reconciliation note with real content. My own earlier framing
("now-redundant prose pointers") had overstated it from one example. Stripping would have deleted
information to satisfy an instruction premised on my error.
