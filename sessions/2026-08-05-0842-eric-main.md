## Task 2: The e2e sign-in race is WebKit-only, and the prescribed fix does nothing (#659)

**Completed:**

- **#659 parked and left OPEN**, retitled, `points:2` dropped, body carrying the full trace with
  the disproven claims struck through rather than deleted.

**Both of the issue's load-bearing claims were wrong, and I only found out by measuring.** It said
CI loses this race because CI runs `next dev`. Chromium won every attempt under `E2E_PROD=0` —
cold server, uncompiled target route, reported shape and purpose-built shape. WebKit lost first
try. The variable is the ENGINE. That collapses "eleven specs exposed": all eleven are
Chromium-only, and the sole WebKit project is already scoped to the one spec that has the guard.

**The interrupter is Next's client router, found with `framenavigated` instrumentation.** `POST
/crew/auth` → 303 → `GET /crew` → URL match → a second navigation to `/crew` at ~150ms with **no
network request behind it**. Not app code: `/crew` has no `useRouter`, `router.replace` or
`router.refresh`. Everything downstream followed from stopping to instrument instead of theorising.

**Three fixes, each obviously right until measured.** `waitForLoadState("load")` — what the issue
prescribes — resolves in ~2ms because the document is already loaded. `document.readyState` reads
`"complete"` at that same instant with a guard and without one; I had written two tests on it and
**both passed identically in both directions, so I deleted them** rather than ship tests that
cannot fail. Waiting on hydration (`__reactProps$`, the repo's own idiom) fixed the admin path
across 3 repeats and still lost the crew path 2 runs in 3.

**Stopped by the operator, correctly, for the second time today.** What remained was waiting on a
navigation Next fires on its own schedule with no public signal — countable events with a bounded
fallback, or a sleep — to protect specs running on an engine that does not lose the race. Shipping
the partial fix would have been the worst of the three options: a half-working fixture plus a
flaky guard test is the exact "flaky CI, re-run it" pattern #659 was written to kill.

**The negative control is what killed the two dead tests, and it is the reusable lesson.** Reverting
the fix via a file copy (not `git checkout` — Task 3 of Session 77 cost a redo that way) and
re-running showed the readyState assertions green in both directions within one run.
