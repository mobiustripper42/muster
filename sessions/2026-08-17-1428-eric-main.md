**Three things worth remembering:**
- **The bug was a missing line, not a wrong one.** `notifyTripChanges` is opt-in, so a caller
  written later just silently stops telling crew. Every existing caller's test passed the whole
  time — you cannot write a behavioural test for a caller that doesn't exist yet. Hence a
  source-reading guard, same trade `app/lib/time-clock-gate.test.ts` makes.
- **The guard quoted its own documentation as evidence.** First cut matched the flag against
  whole-file raw source — and every governed file *explains* the flag in a comment beside the
  call, so deleting the flag left the test green. Caught by `@code-review`, not by me. Now strips
  comments and matches per call site.
- **The cancel path's own comment was half-true and had been for months.** "Re-form so the shift
  collapses and its crew are told" only held when the cancelled trip was the day's *only* trip.
  A comment stating an intent the code half-delivers reads as verification.

**Filed, not fixed:** issue #766 — `formShifts` writes inside its loop with no transaction or
lock. A mid-loop throw loses a notice *permanently* (the tick then sees no diff); two overlapping
runs duplicate one. Both pre-date this, both got more reachable with it. Found by `@code-review`.

**Code review:** `@code-review` — 3 findings: the guard weakness fixed in `f6d030a`; two

**Three things worth remembering:**

  did.** #736's guard matched its own documentation. #765's cancel comment described an intent the

  exercised, a type carrying a second meaning one adapter cannot represent, and a netting comment

  body falls back to bare "shift changed." Recorded in DEC-158 rather than papered over; it is the
  strongest argument for finishing #769.
