## Task 3: Write only the vessel-days that moved (#998)

**Completed:**
- **`sameShift` + a conditional `saveShift`** in `src/builder/form-shifts.ts`. Every run used to rewrite every vessel-day it visited, changed or not — one booking rewrote twelve unrelated rows (#957), and the tick does it across every vessel-day that has ever existed. DEC-167's point: the cost is cadence × work, and nothing displays the product.
- **Field by field, never a deep equal.** Both sides omit an absent optional rather than setting it null (conditional spreads in the literal; `opt()` in `postgres-repository.ts`), so a structural compare would work today and break the first time an adapter normalised differently. The explicit list also fails loudly when `Shift` gains a field — which matters more here than usual: the literal is rebuilt from scratch (merge clears `splitCutTime`; a spread would resurrect it), so a field missing from it is already erased on every form, and a conditional write makes that erasure **intermittent** rather than constant. Both sites carry the same warning now.
- **The notice diff is deliberately outside the guard.** It reads `existing` against the built row on its own terms, and an unchanged pair produces no diff anyway. The trap was real: that block lives in the same `if (existing)` branch as the counter, and skipping the branch rather than the write would have stopped telling crew their day moved — on exactly the days it did and nowhere else.
- **`shiftsUpdated` counts changes, not writes.** One non-test reader (`app/api/cron/xola-pull/route.ts`), which says so at the site. A steady re-pull reports 0 rather than the size of the fleet.
- **Two existing tests changed, both correctly.** `is idempotent` asserted 3 (a write count); one day changed, so 1. The `#766` case stubbed `saveShift` to throw on a day nothing had moved — the write no longer happens, so its fixture changes that day for real. Without it the throw would never fire and the case would have passed trivially.
